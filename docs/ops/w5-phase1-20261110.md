## 3. Conflict, replay, outage, revocation paths

- Concurrent semantic updates on the same ticket from two browser tabs both committed
  (revision 8 → 10); the final title is the last writer. Semantic evolution operations
  compose; they are not whole-document CAS.
- Exact replay of the same operation id is idempotent: first `POST .../operations`
  returned 200 at revision 12, the identical second request returned 200 and the
  revision stayed 12 (no double update).
- The same operation id with a different payload is refused with
  `409 operation_id_conflict` and changes nothing.
- A stale whole-document write is still refused (W4 evidence; revision did not change).
- Origin real stop was **not** performed: no isolated staging Origin can be safely
  stopped and restored in this environment. The W4 browser test that aborts the
  `/__ato/**` requests remains a network-failure test and is reported as such.
- Revocation through a path other than the PWA: the binding revoke above used the
  plain HTTP API (not the PWA), and the W4 fix is in the authorization predicate shared
  by every caller. The MCP connection path was not exercised — staging has no MCP OAuth
  connection for these accounts, so it stays unverified rather than claimed.
